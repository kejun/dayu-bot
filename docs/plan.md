## 阶段总览

### 阶段 1 · 主机文字指令驱动 Agent + iCTRL

**目标**：在 Mac 上输入文字，完成手机微信发送与邮件查看，且**无独立业务 API**。

- [ ] iPhone 装好 iCTRL，`bridge pair` 成功
- [ ] `bridge phone device_info` 返回手机信息
- [ ] `bridge install-skill` 把设备 `/skill` 交给 Hermes
- [ ] `bridge ask "给张三发微信：今晚8点开会"` → iCTRL 实际操作手机并核查
- [ ] `bridge ask "打开手机邮件，看看今天有没有重要邮件"` → 基于实际读到内容作答
- [ ] 交回控制权（回到发起 App）

**验收**：两个场景真实跑通，日志中可见 iCTRL 的 `tap/type/page_source` 调用序列。

### 阶段 2 · ESP32 录音 / 播放 / 联网

- [ ] 板子跑通 Waveshare 官方显示/触摸/音频示例
- [ ] 按住录音（麦克风 + ES8311），松开上传到主机
- [ ] 主机回传音频在终端扬声器播放
- [ ] 屏幕显示 idle/recording/processing/result

**验收**：对板子说"测试"，主机能收到音频并回放。

## 阶段 3 · 串起语音 + Agent + 手机

- [ ] STT：音频 → 文本
- [ ] 文本 → Hermes → iCTRL → 手机
- [ ] 结果文本 → TTS → ESP32 播放
- [ ] 屏幕显示简短状态与结果

**验收**：**一句语音指令完成真实手机操作并返回结果**（PRD 首版验收 1、2）。

## 阶段 4 · 追问、取消、最少状态

- [ ] 信息不足 → 屏幕+语音追问，回答继续当前任务
- [ ] 取消 → 停止派发后续动作，不谎报"已取消"
- [ ] 断线重连不重发旧录音；重复 request_id 返回已有状态
- [ ] 未知结果如实报"结果未确认"

**验收**：PRD 首版验收 3、4。

## 阶段 5 · 桌宠 + 现成调度

- [ ] 桌宠动画映射真实状态（复用 Hermes `pets`）
- [ ] `hermes cron` 定时触发**同一条** iCTRL 手机任务路径
- [ ] 定时任务与主动任务共用串行手机通道，不打断进行中的任务

**验收**：PRD 首版验收 5。

- 多设备控制、唤醒词、连续对话、多套语音服务切换、复杂协议协商
